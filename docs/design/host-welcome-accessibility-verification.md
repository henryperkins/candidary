## Linux announcement correction

The follow-up at local `31d87aa` reproduced silent spontaneous missing-target speech after earlier speech ended. The conditional, populated status paragraph was added too late for reliable live-region presentation. The final fix keeps both the polite/atomic status container and its text paragraph mounted, with the empty paragraph visually hidden. Recovery updates existing text; it preserves heading focus, one status owner and the original message typography. This follows [W3C ARIA22's status-container lifecycle and atomicity guidance](https://www.w3.org/WAI/WCAG21/Techniques/aria/ARIA22).

The focused UI lane ran `npm run test:unit -- tests/ui/host-welcome-tour.test.tsx -t 'keeps recovery announcements in a persistent polite live region|keeps missing-target and failed-preference recovery'`: RED for the missing persistent node, then **2 passed / 31 skipped**. Refining the text paragraph's lifetime also had a focused RED/GREEN record. Existing JSDOM `scrollBy` diagnostics are recorded; they do not substitute for browser evidence. The single touched browser case, `npx playwright test --config playwright.welcome.config.ts tests/e2e/host-welcome.spec.ts --project=desktop -g 'failed-save replay and missing target expose one recoverable status'`, passed **1/1**. A first over-anchored selector found no tests and is preserved as a failed selection attempt. A container-only native attempt remained silent and is preserved separately. The final native follow-up repeated only the missing-target window and passed; the earlier exit captures were reused.

Evidence is under `output/playwright/host-welcome-findings-2026-10-11/reader/`: final `result.json`, `missing-target-spontaneous-{speech,protocol}.txt`, WAV and `audio-validation.json`; `native-red/` retains the original silent window and successful exit captures; `native-persistent-container-only/` retains the unsuccessful intermediate attempt. `failed-setup-{1,2,3}/` contains environment/input setup failures before app qualification. Run the sequence below on each named pair. These are verification targets, not a claim of a supported-browser matrix:

- **Linux / Chromium / Orca:** use the isolated X11/DBus runner below. Confirm live-region monitoring is enabled; changing it mid-capture invalidates that window. Orca's [live-region commands](https://help.gnome.org/orca/commands_live_regions.html) document monitoring and message review.
- **Linux / Firefox / Orca:** repeat the same sequence in native Firefox with a separate profile and the same synthetic fixture. Preserve the Firefox version and separate speech artifacts.
- **macOS / Safari / VoiceOver:** enable VoiceOver through Accessibility or Command-F5, note the VO modifier and Quick Nav/cursor tracking settings, and enable Safari keyboard navigation for the Tab checks. Use VoiceOver web navigation and activation as well as ordinary Tab/Shift-Tab; capture the caption panel plus audio and human notes. See Apple's [VoiceOver setup](https://support.apple.com/guide/voiceover/turn-voiceover-on-or-off-vo2682/mac) and [web commands](https://support.apple.com/guide/voiceover/vo27972/mac).
- **Windows / Chromium and Firefox / NVDA:** record each browser separately. Enable Tools → Speech Viewer, capture it with audio, and test browse navigation plus Tab/Shift-Tab. Record any NVDA+Space mode change rather than silently treating it as an app transition. On iOS Safari with VoiceOver and Android Chrome with TalkBack, explore the dialog using reader gestures, activate controls, rotate, enlarge text, and reach internally scrolled actions. Use Apple's [iPhone VoiceOver guide](https://support.apple.com/guide/iphone/turn-on-and-practice-voiceover-iph3e2e415f/ios) and Android's [TalkBack gesture guide](https://support.google.com/accessibility/android/answer/6151827?hl=en) for the installed versions. If a physical keyboard is connected, run the keyboard exit checks separately. A desktop proxy does not sign off this row.

Focus starts on its heading. Full body should not be repeated by both dialog and heading. | Settled open utterance, dialog description and actual focus. Keep automatic and manual entry distinct. Link-only hosts remain manual. |
| 2. Use Tab/Shift-Tab and reader navigation through the introduction. | Close, Skip and the recommendation are named controls; background work controls are excluded while modal.
