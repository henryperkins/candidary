## Verdict

Not implementation-ready at `54bbc69d97a56e283ec16cef102c7dd009e1f9bc`. I found **6 P1 blockers and 3 P2 defects** across all five Slice 5 plans. Slice 6 was correctly excluded.

## Findings

1. **P1 — Full upload authority is still not atomically rechecked.** The global contract requires the same authority through reserve, refresh, claim, and commit ([plan:22](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:22)), but the detailed implementation adds credential checks only to claim/commit and checks only account/membership or access token, leaving guest behavior unchanged ([plan:355](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:355)). That omits host-session revocation/expiry/auth-version, manager-link and guest event sessions, and route-auth→reserve races, contrary to the governing specification ([spec:67](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/specs/2026-08-23-host-gallery-lifecycle-contribution-design.md:67)). Current claim/commit return only null/boolean ([media.ts:1252](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/db/media.ts:1252)), so `receiveMediaUpload` maps authorization loss to a 409 conflict, not the promised generic 403 ([storage/media.ts:266](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/storage/media.ts:266)). Define one authority predicate plus bindings for every phase and tagged repository outcomes that distinguish forbidden from state conflict.

2. **P1 — Manager cancellation can permanently delete a stored original.** The plan allows only reserved/failed cancellation ([plan:25](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:25)), but Task 5 specifies only a route-level state check before reusing the current deletion path ([plan:419](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:419)). `MediaRepository.delete` deliberately rereads a reserve→stored winner and then deletes the stored row ([media.ts:3102](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/db/media.ts:3102)). Add an actor-scoped repository CAS restricted to `reserved`/`failed` and a Worker test that finalization lands between the route read and DELETE.

3. **P1 — The proposed rotation guard does not produce one winner.** The plan claims `revoked_at IS NULL` makes concurrent rotations single-winner ([plan:452](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:452)), but its role-wide UPDATE ([plan:491](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:491)) simply lets the second serialized caller revoke the first caller’s replacement. A SQLite probe produced `changes() = 1` for both callers, leaving the first returned link dead. The schema has no unique-active-token constraint ([0001_core.sql:36](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/migrations/0001_core.sql:36)). Capture the exact predecessor token ID and CAS that ID; add a two-caller test asserting one success.

4. **P1 — Account actor creation can miss a concurrent rotation.** Task 3 requires a new actor to carry the current Manager token ([plan:242](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:242)), while rotation rebinds only actors visible inside its batch ([plan:451](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:451)). A token read followed by rotation followed by actor insertion creates a live actor bound to the revoked predecessor; the partial unique index then prevents creating a replacement ([plan:97](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-authority.md:97)). Use an atomic guarded `INSERT … SELECT` from the active token, with retry/re-read, and test ensure-versus-rotation.

5. **P1 — The browser cannot observe the terminal authorization failures the dialog promises to handle.** The dialog requires terminal authorization/lifecycle handoff ([plan:23](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-dialog.md:23)), but current XHR turns every non-2xx content response into a generic `Error` ([browser-upload-transport.ts:79](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/src/features/uploads/browser-upload-transport.ts:79)), and the queue then retains only its message string ([upload-queue.ts:143](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/src/features/uploads/upload-queue.ts:143)). The proposed interfaces add no terminal-error channel. Preserve `ClientApiError` codes from XHR and surface terminal reserve/upload/finalize errors to the dialog; test a real revoked content PUT through transport, queue, and dialog rather than only mocking a cleanup outcome.

6. **P1 — Successful Album start does not advance the revision token.** The new request carries `expectedRevision` ([plan:120](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-album-era-reconciliation.md:120)), but implementation guidance only says to match it ([plan:130](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-album-era-reconciliation.md:130)). Current Start updates entries and `saved_at` without incrementing revision ([album.ts:535](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/db/album.ts:535)). Consequently a cohost holding the pre-start revision can overwrite the successful start with a stale PUT. Increment revision on every successful new-client Start and test that a pre-start PUT conflicts afterward for both choices.

7. **P2 — The safety-ladder checkpoint depends on work it explicitly defers.** The account plan excludes pause verbs ([account plan:30](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-account-lifecycle-and-rotation.md:30)) but requires the exact “Pause / Resume guest uploads” ladder row ([account plan:363](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-account-lifecycle-and-rotation.md:363)). The current component still says “Pause photo delivery” / “Reopen photo delivery” ([component:33](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/src/components/ManagerPhotoIntakePanel.tsx:33)); the final checkpoint owns that change ([pause plan:83](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-pause-scope-and-first-run.md:83)). Move that ladder row and C-16 closure to the final checkpoint or reorder ownership.

8. **P2 — The fullscreen test incorrectly requires unrelated surfaces on the gallery-only route.** The test requires Guestbook and My deliveries on both routes ([pause plan:50](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-pause-scope-and-first-run.md:50)), while fullscreen intentionally renders only the gallery and close control ([EventPage.tsx:156](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/src/pages/EventPage.tsx:156)). The specification requires the fullscreen Gallery to share availability/projection rules, not duplicate every main-page panel ([spec:25](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/specs/2026-08-23-host-gallery-lifecycle-contribution-design.md:25)). Assert Guestbook/My deliveries on the main route and gallery projection parity on fullscreen.

9. **P2 — The expired-event availability projection is unreachable through the named API test.** The dialog plan expects an expired Manager event to return `reason: 'event-unavailable'` ([plan:59](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/docs/superpowers/plans/2026-08-27-host-gallery-manager-upload-dialog.md:59)), but account authorization throws `EVENT_EXPIRED` before projection ([manager.ts:41](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/auth/manager.ts:41)), and the route calls authorization first ([event.ts:26](/home/henry/candidary/.worktrees/gallery-roadmap-remediation/worker/routes/event.ts:26)). Either remove the dead wire reason and assert the canonical 410, or define and unit-test a deliberately non-wire selector plus how stale clients transition to it.
